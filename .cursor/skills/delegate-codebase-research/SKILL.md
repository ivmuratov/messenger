# Delegate Codebase Research

Используй этот skill для широкого исследования перед планированием или реализацией. Для точечного поиска известного символа или чтения 1–3 известных файлов исследуй напрямую без subagent.

## Главный принцип

Во время research-фазы main-агент координирует исследование, но не выполняет его самостоятельно.

- MUST NOT использовать `ReadFile`, `rg`, `Glob`, semantic search или shell-поиск для исследования кодовой базы.
- MUST делегировать поиск subagent типа `researcher`.
- MUST считать структурированные результаты researcher основным источником контекста и не повторять их поиск для проверки.
- MAY анализировать запрос, определять scope, запускать subagent и синтезировать их ответы.
- После завершения research-фазы main-агент MAY читать найденные файлы, если пользователь запросил планирование или реализацию.

## Определение scope

Выбери только области, которые действительно могут быть затронуты:

- `packages/ui` — кросс-платформенные компоненты, токены, web/mobile реализации.
- `packages/core` — бизнес-логика, API, типы, hooks, store, selectors.
- `apps/web` — web routes, layouts и feature-модули.
- `apps/mobile` — Expo navigation, screens и feature-модули.
- `apps/ui-storybook` и тестовая инфраструктура — stories, visual/component/e2e testing и tooling.

Не запускай researcher для каждого слоя механически. Примеры:

- Кросс-платформенная feature с бизнес-логикой: `ui`, `core`, `web`, `mobile`.
- Новый визуальный компонент: `ui` и только его реальные consumers.
- Изменение core API: `core` и приложения, которые его потребляют.
- Изменение тестового tooling: соответствующее приложение, package или CI.

## Неизвестный scope

Если по запросу нельзя уверенно выбрать области, сначала запусти одного `researcher` как scoper. Он должен вернуть:

1. затронутые области;
2. обоснование для каждой области;
3. отдельный research-вопрос для каждого следующего researcher;
4. области, которые исследовать не требуется.

После ответа scoper запусти нужных researcher по областям.

## Параллельный запуск

Когда области независимы, запускай все subagent `researcher` параллельно в одном вызове инструментов.

Для каждого researcher используй:

- `subagent_type: "researcher"`
- `run_in_background: false`, если пользователь явно не попросил фон
- отдельное конкретное `description`
- отдельный scope без дублирования ответственности

Не делегируй одному researcher весь кросс-платформенный запрос, если его можно разделить по архитектурным границам.

## Шаблон промпта

Каждый subagent не видит исходный запрос и контекст main-агента. Передавай автономный промпт:

```text
Full Repository Path: <absolute repository path>

User Goal:
<полная формулировка цели пользователя>

Assigned Scope:
<один слой, приложение или конкретная область>

Research Questions:
- <что найти>
- <какие существующие паттерны и точки интеграции определить>
- <какие контракты с другими слоями проверить>

Boundaries:
- Read-only: ничего не изменять.
- Исследовать Assigned Scope глубоко.
- За его пределами проверять только прямые зависимости и контракты.
- Не проектировать несвязанные улучшения.

Return:
- краткий вывод;
- точные пути релевантных файлов;
- существующий поток данных и зависимости;
- рекомендуемые точки изменений в Assigned Scope;
- входные и выходные контракты с другими слоями;
- тесты и команды проверки, относящиеся к scope;
- риски, пробелы и неизвестные.
```

## Синтез

После завершения всех researcher main-агент:

1. объединяет результаты по слоям;
2. устраняет дублирование в описании, не выполняя новый поиск;
3. сопоставляет межслойные контракты;
4. явно отмечает противоречия и неизвестные;
5. формирует единый implementation map или отвечает на вопрос пользователя.

Если результаты противоречат друг другу или критически неполны, сначала возобнови соответствующий researcher с точечным уточнением. Не переходи к самостоятельному поиску.

```markdown
- `apps/mobile`: ...

## Межслойные контракты
- ...

## Проверки
- ...

## Риски и неизвестные
- ...
```
